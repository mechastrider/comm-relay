# Интерактивные стримы — карта документов

Этот каталог — точка входа для развития интерактивной системы CommRelay.

| Документ | Роль |
|---|---|
| [`vision.md`](vision.md) | Устойчивая продуктовая гипотеза и границы системы |
| [`backlog.md`](backlog.md) | Реестр идей, потенциальных улучшений и реализованных инициатив |
| [`../roadmap.md`](../roadmap.md) | Только согласованный порядок следующих поставок |
| [`../open-questions.md`](../open-questions.md) | Продуктовые и UX-решения, которые ещё должен принять человек |
| [`../research/`](../research/) | Переносимые глубокие исследования и архивные снимки |
| [`../../openspec/specs/`](../../openspec/specs/) | Канон реализованного поведения |

## Жизненный цикл инициативы

```text
локальный разбор сессии в var/session_analysis/
    → candidate / needs_research в backlog.md
    → needs_decision в open-questions.md
    → planned в roadmap.md
    → in_progress в openspec/changes/
    → implemented в openspec/specs/
```

`backlog.md` — навигационный реестр, а не спецификация. Он хранит короткий результат, статус и ссылки, но не копирует подробный контракт из OpenSpec.

## Правила обновления

- Сначала ищите существующую `INT-NNN`, чтобы не плодить дубликаты одной идеи из разных эфиров.
- Одна строка описывает один независимо поставляемый результат. Смешанные инициативы разбиваются; статус `partially_implemented` не используется.
- `implemented` ставится только после сверки с canonical spec. Наличие прототипа или незакрытого change недостаточно.
- Приоритет `now` / `next` / `later` появляется только после явного продуктового решения; сырые идеи не получают приоритет автоматически.
- Из `candidate` и `needs_decision` нельзя начинать реализацию без отдельного решения человека.
- Локальные файлы из `var/` не коммитятся и не используются как ссылки в Git-документах. Если доказательство нужно сохранить для команды, создаётся обезличенный research-note.

Workflow для агентов: [`interactive-research`](../../.agents/skills/interactive-research/SKILL.md).
