## OBS overlay

### В OBS чёрный квадрат вместо чата (Linux)

**Симптомы:** CommRelay запущен, коннектор подключён (`connected`), сообщения видны в админке, URL overlay скопирован из **OBS → Setup**, но в источнике **Browser** (Браузер) — сплошной чёрный прямоугольник без текста.

**Решение (подтверждено на Linux Mint):** отключите аппаратное ускорение Browser Source в OBS.

1. **Файл** → **Настройки** (или **File** → **Settings** в английском интерфейсе).
2. Слева откройте **Расширенные** / **Advanced**.
3. Прокрутите до раздела **Источники** / **Sources**.
4. Снимите галочку **«Включить аппаратное ускорение для источника "Браузер"»**  
   (в английской локали: **Enable Browser Source Hardware Acceleration**).
5. Нажмите **Применить** / **ОК** и **полностью перезапустите OBS**.
6. В свойствах Browser Source нажмите **Обновить кэш текущей страницы** / **Refresh cache of current page**.

**Почему это помогает:** Browser Source в OBS использует встроенный Chromium (CEF). На Linux аппаратное ускорение для браузерных источников появилось в OBS Studio **31.1** и может конфликтовать с драйвером GPU, Wayland/X11 или конкретной сборкой OBS (apt, Flatpak, PPA). CommRelay overlay с прозрачным фоном в таком случае часто выглядит как чёрный прямоугольник, хотя страница загружается.

**Заметки:**

- На видеокартах **NVIDIA** OBS иногда **сам отключает** аппаратное ускорение браузера из‑за несовместимости драйвера; в логе OBS может быть строка `[obs-browser]: Blacklisted driver detected, disabling browser source hardware acceleration.` — это ожидаемо.
- Если галочка уже снята, а квадрат остаётся — попробуйте **включить** её, перезапустить OBS и снова проверить (на части систем помогает обратное).
- Для overlay CommRelay обычно достаточно **программного** рендеринга CEF; отключение HW accel редко заметно на простом текстовом чате.

**Ссылки OBS:**

- [Browser Source (KB)](https://obsproject.com/kb/browser-source)
- [Установка OBS на Linux](https://obsproject.com/kb/linux-installation)

### Как понять, проблема в CommRelay или в OBS

Перед настройкой OBS откройте overlay в **обычном браузере** (не в OBS):

```
http://127.0.0.1:17877/overlay
```

| Что видите в браузере | Где искать причину |
|----------------------|-------------------|
| Сообщения приходят при новом сообщении в чате | CommRelay в порядке; настраивайте OBS (URL, кэш, HW accel, размер источника) |
| Пусто, хотя в админке сообщения есть | CommRelay: TTL overlay, тема, WebSocket; см. раздел ниже |
| Страница не открывается | CommRelay не запущен или другой порт в `config.json` |

Быстрая проверка рендерера без live-чата:

```
http://127.0.0.1:17877/overlay?preview=sample&preview_background=checker
```

Должны появиться тестовые сообщения. Тот же режим есть в админке: **OBS → Appearance → Preview**.

### Сообщения есть в админке, но не в overlay (браузер и OBS)

1. **Message TTL** — в **OBS → Appearance** выставьте **0**, нажмите **Save settings**. По умолчанию сообщения исчезают через 20 секунд; старые записи при открытии overlay не показываются.
2. **Тема Text only** — светлый текст на прозрачном фоне в обычном браузере почти не виден. Для проверки выберите **Default** или откройте `?preview_background=dark`.
3. **WebSocket** — внизу админки счётчик **WS:** при открытой вкладке `/overlay` должен быть **2 или больше**. В DevTools (F12) на вкладке overlay проверьте соединение `ws://127.0.0.1:17877/ws`.
4. **Кэш OBS** — после смены настроек overlay: правый клик по источнику → **Refresh cache of current page**.
5. **URL и порт** — копируйте URL из **OBS → Setup**; при смене порта в настройках обновите Browser Source.

### OBS на Linux: Browser Source недоступен или пустой (Flatpak)

Не во всех сборках OBS из репозиториев дистрибутива есть полноценный Browser Source. Для overlay и dock рекомендуется OBS из [официального PPA](https://obsproject.com/kb/linux-installation) (`ppa:obsproject/obs-studio`) или проверенная сборка с Flathub.

У **Flatpak**-версии OBS доступ к `127.0.0.1` иногда ограничен песочницей; если overlay открывается в системном браузере, но не в OBS — проверьте сетевые разрешения Flatpak или используйте нативный пакет.

## YouTube

### Нужен ли Google OAuth для чата

Нет, если достаточно публичного live chat. По умолчанию CommRelay использует **Simple (video URL)**: укажите handle канала (`@name`) или URL эфира в **Connections** — Google Cloud и вход в аккаунт не нужны.

### Почему Connect открывает системный браузер

В режиме **API (OAuth)** вход Google выполняется в вашем обычном браузере (Chrome, Firefox и т.д.), а не во встроенном окне CommRelay. Так безопаснее: видна адресная строка `accounts.google.com`, пароль не вводится внутри приложения. После успешного входа вкладку браузера можно закрыть и вернуться в CommRelay.

## Приложение (Linux)

### Нужны ли системные зависимости GTK/WebKit

Да, для **desktop-сборки** из [Releases](https://github.com/mechastrider/comm-relay/releases):

```bash
sudo apt install libgtk-3-0 libwebkit2gtk-4.1-0
```

Если приложение **уже открывается** и админка работает, эти библиотеки установлены. Их отсутствие обычно не даёт запустить бинарник вовсе, а не ломает только overlay.

### Где лежит config.json

`~/.config/comm-relay/config.json` — см. таблицу в [`README.md`](../README.md).

## YouTube

### Почему вход Google открывается в браузере, а не в окне CommRelay

**Так и задумано.** Для режима **API (OAuth)** CommRelay открывает страницу входа Google в **системном браузере** (Chrome, Firefox и т.д.), где видна адресная строка и работают привычные менеджеры паролей. Окно desktop-приложения больше не перенаправляется на `accounts.google.com`.

**Что делать:**

1. В **Connections** выберите **Connection mode → API (OAuth)**.
2. Сохраните **OAuth client ID** и **client secret**, нажмите **Save**.
3. Нажмите **Connect** — откроется браузер.
4. После успешного входа закройте вкладку с сообщением «YouTube connected» и вернитесь в CommRelay.

Если браузер не открылся, скопируйте ссылку из баннера в админке или проверьте, что `xdg-open` / аналог доступен в системе.

**Без OAuth:** для большинства стримов достаточно режима **Simple (video URL)** по умолчанию — укажите `@handle` канала без Google Cloud.
