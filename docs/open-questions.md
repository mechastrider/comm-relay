# Открытые вопросы

Статус: **вопросы на подумать**, не спецификация и не план работ.

**Workflow для агентов:** skill [`.agents/skills/open-questions/SKILL.md`](../.agents/skills/open-questions/SKILL.md).

Сюда попадают продуктовые и UX-вопросы, которые:

- ещё **не решены** и не должны тянуть за собой код;
- важны для обсуждения, но **рано** для `docs/roadmap.md` или OpenSpec change;
- часто возникают из сессии с оператором или агента («казалось, что функция пропала», «куда деть кнопку»).

Канон **уже реализованного** поведения: [`openspec/specs/`](../openspec/specs/).  
Горизонт **согласованных** инициатив: [`roadmap.md`](roadmap.md).  
Глубокий разбор темы (таблицы, сверка с кодом): [`research/`](research/).

## Куда что класть

| Тип | Файл | Когда |
|-----|------|--------|
| Короткий нерешённый вопрос | **этот файл** (`open-questions.md`) | Нужно зафиксировать проблему/альтернативы, решения ещё нет |
| Развёрнутый разбор | `docs/research/<topic>.md` | Много контекста, сверка с `main`, несколько подтем |
| Обязательство в продукте | `docs/roadmap.md` | Вопрос решён; приоритет и направление согласованы |
| Контракт на реализацию | `openspec/changes/<name>/` | Готовы писать proposal/specs/design/tasks |
| Конкретная задача в очереди | `docs/task-tracker.md` + `docs/tasks/CR-*.md` | Есть чёткий scope и acceptance |

## Статусы записи

- `open` — обсуждается, решения нет
- `promoted` — перенесено в roadmap или OpenSpec (указать ссылку)
- `resolved` — решение принято и отражено в specs/roadmap/FAQ (указать где)
- `wont-fix` — сознательно не делаем (кратко почему)

## Шаблон новой записи

Скопируйте блок ниже в конец файла, замените `OQ-NNN` на следующий номер.

```markdown
### OQ-NNN: Краткий заголовок (ГГГГ-ММ-ДД)

**Статус:** `open`  
**Контекст:** откуда вопрос (сессия, редизайн, обратная связь).  
**Вопрос:** одна формулировка, на которую нужен ответ.  
**Почему важно:** для кого и какой сценарий ломается или путается.  
**Как сейчас:** фактическое поведение + ссылка на spec/архив при необходимости.  
**Варианты:** краткий список альтернатив (если уже видны).  
**Связи:** ссылки на `openspec/`, `research/`, issue.  
**Продвижение:** куда перейдёт после решения (`roadmap` / OpenSpec change / FAQ / —).
```

## Реестр

### OQ-001: Видимость URL с `preset` для OBS в Studio (2026-09-03)

**Статус:** `open`  
**Контекст:** после редизайна Studio (follow-active как основной URL) оператору показалось, что копирование ссылки с `?preset=<id>` «пропало». Функция есть в «Закреплённый пресет (дополнительно)» и в overflow превью, но блок глубоко спрятан.  
**Вопрос:** какой URL должен копироваться **по умолчанию** в Studio — follow-active (без `preset`) или pinned (с `preset` текущего редактируемого пресета)?  
**Почему важно:** сценарий «разные сцены OBS → разные пресеты» опирается на pinned URL; сценарий «одна ссылка на весь эфир» — на follow-active. Сейчас основная кнопка обслуживает второй сценарий, первый легко не заметить.  
**Как сейчас:** основное поле и «Копировать ссылку OBS» (режим «Основное») — без `preset`; pinned — в `<details>` / advanced. Зафиксировано в [`openspec/changes/archive/2026-08-29-interactive-console-redesign/`](../openspec/changes/archive/2026-08-29-interactive-console-redesign/) и [`openspec/changes/archive/2026-08-31-studio-surface-centric-redesign/`](../openspec/changes/archive/2026-08-31-studio-surface-centric-redesign/).  
**Варианты:**

1. Оставить follow-active основным; улучшить discoverability pinned (не сворачивать, подписи, onboarding).
2. В Studio по умолчанию копировать pinned редактируемого пресета; follow-active — в advanced.
3. Две явные кнопки: «Для этой сцены (preset)» и «Следовать активному пресету».
4. Контекстно: Studio → pinned, Эфир/общие настройки → follow-active.

**Связи:** archive changes выше; mockup с отдельной кнопкой pinned — [`mockups/studio-surface-centric.html`](mockups/studio-surface-centric.html).  
**Продвижение:** OpenSpec change (admin-and-dock / Studio OBS URLs) после выбора варианта.
