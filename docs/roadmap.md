## Статус

**Стримовый MVP достигнут** (этапы 1–5 в концепте). Реализованы зрители, лидерборд и механизм команд/наград (6a–6b).

Архитектурное направление frontend после MVP зафиксировано отдельно: [поэтапная admin-only миграция на компонентный фреймворк](research/frontend-refactoring.md). Она не меняет продуктовые фазы ниже, но рекомендует до усложнения редакторов и rules engine укрепить frontend tests, framework-neutral границы и build pipeline; OBS-поверхности остаются независимыми нативными ES modules.

Дальше CommRelay остаётся **локальным** приложением (один процесс, localhost, без облачного relay) и наращивает роль **движка социальных событий стрима**. Главная продуктовая гипотеза — отмечать не объём чата, а вклад зрителя, а затем превращать заработанный прогресс в интерактивы:

```text
Contribution → Award → Session Score + XP + Credits → Redemption → Overlay Action
      ↑                                                                  │
      └──────────────────── новый момент в чате ─────────────────────────┘
```

Контент стрима (портреты, подписи, тематика MW5) — **настройки оператора**, не ядро продукта.

## Хранение

| Слой | Где | Что |
|------|-----|-----|
| Настройки оператора | `config.json` | платформы, overlay, секреты OAuth/SOCKS, пресеты, граница суток |
| Зрители и факты | SQLite рядом с конфигом | идентичности, склейки, счётчики, сессии, команды, награды, журнал взаимодействий |

Конфиг **не** переносится в SQLite: вложенные пресеты, секреты и ручное редактирование уже работают. Оба файла лежат в одном каталоге; бэкап = копия папки.

SQLite — встроенный, **pure Go** (без CGO), чтобы сохранить один исполняемый файл на Windows/macOS/Linux.

Полный архив чата в БД **не** входит в ближайшие фазы: только агрегаты по зрителю. Кольцо последних сообщений в памяти остаётся для админки, dock и overlay.

## Зрители и склейка

Сообщение с платформы всегда привязано к **идентичности** `(platform, user_id)`. Канонический **зритель** может иметь несколько идентичностей (Twitch + YouTube, два аккаунта на одной платформе и т.д.).

```text
identity (twitch, 123)  ──┐
identity (youtube, UC…) ──┼─ viewer #42  →  message_count, xp
identity (vk, 99)       ──┘                 (после склейки)
```

Пока склейки нет, каждый новый `(platform, user_id)` создаёт своего зрителя. Отображаемое имя и аватар — last-seen с идентичности; оператор может задать имя канонического зрителя в админке.

**Склейка** доступна в любой момент, но основной сценарий — **после стрима**: оператор видит двух людей, понимает что это один, и сливает в одного зрителя. Счётчики складываются, идентичности начинают указывать на каноническую запись, лидерборд показывает одну строку.

В админке нужно **отдельное управление зрителями**: поиск по имени / логину / id платформы, карточка (идентичности, счётчики за стрим / сутки / всё время), действие «склеить с…». Разъединение сразу не обещаем; факт склейки стоит журналировать, чтобы потом можно было подумать про undo.

Лидерборд и статистика всегда считаются по **каноническому зрителю**, не по сырой идентичности.

## Счётчики

Сейчас реализованы два независимых числа:

- `message_count` — сколько строк чата пришло (факт).
- `xp` — очки опыта за тихую activity-награду и ручные награды оператора.

Сообщения чата сами по себе XP не дают: `message_count` остаётся фактом активности, тихая activity-награда имеет интервал и лимит за стрим (настройки в **Settings → Данные**), а основной прогресс дают contribution-награды через **Reward**. Команды XP не меняют.

В [`Interactive System v1`](interactive-system-v1.md) будущая экономика разделена на:

- **Session Score** — рейтинг текущего эфира, не расходуется;
- **Persistent XP** — уровни и долгосрочный прогресс, не расходуется;
- **Credits** — баланс для покупки overlay-интерактивов.

Credits и уровни — следующие фазы; текущие окна session/day/all уже называются XP.

## Периоды лидерборда

Три независимых среза. Один эфир через полночь **не** должен ломать «этот стрим».

| Период | Как начинается / сбрасывается |
|--------|-------------------------------|
| `session` | Кнопка **«Новый стрим»** в админке закрывает текущую сессию и открывает новую. Пока сессии нет — она открывается при необходимости (чтобы первая установка работала без кнопки). |
| `day` | Календарные сутки оператора с **настраиваемым часом сброса**, по умолчанию **06:00** локального времени, **не полночь**. Эфир 22:00–02:00 при сбросе в 06:00 остаётся одним «днём». |
| `all` | Никогда не сбрасывается. |

Сессия и сутки независимы: ночной стрим может быть одной сессией и одним `day` (при сбросе в 06:00) или пересечь границу суток, если эфир задевает час сброса.

OBS Browser Source: `/overlay/leaderboard` с query вроде `period=session|day|all`. Чат `/overlay` не смешивается с лидербордом — это **вторая панель** в сцене.

## Команды чата и награды (реализовано)

Два каталога в **Audience**: **Команды** и **Награды**. При первом запуске — удаляемые примеры `!gg`/`!hi` и Joke (+10) / Advice (+50); после удаления не восстанавливаются. Тематика стрима (Джейк, ComStar, …) — содержимое каталогов, не код CommRelay.

Обработка на **сервере**: целая строка `!команда` → событие → `/ws` → `/overlay/alert` (аватар + надпись на несколько секунд). Команды **не** меняют XP. Очки за поведение — через **Reward** в Live и dock (повторная выдача разрешена). Успешные команды и награды пишутся в журнал взаимодействий для будущих достижений.

Глобальная настройка **скрывать строки команд в overlay чата**: в `/overlay` `!команды` не рисуются, в админке и dock остаются.

Следующий слой: Contribution Rewards, achievements, Reward Library и rules engine. Существующие команды и награды остаются совместимым простым интерфейсом, а не одноразовым прототипом.

## Фазы

### Фаза 6a — зрители, статистика, лидерборд (реализовано)

- SQLite рядом с `config.json`, миграции схемы.
- Идентичности, канонические зрители, склейка, админка зрителей.
- Учёт `message_count` и `xp` (тихая activity-награда и ручные награды).
- Сессии («Новый стрим»), сутки с часом сброса, всё время.
- OBS-панель `/overlay/leaderboard`.

### Фаза 6b — команды и награды (реализовано)

- Каталоги команд и наград (CRUD), удаляемые примеры при первом запуске.
- Серверный `!`-матчинг, кулдаун, `/overlay/alert`; команды не меняют XP.
- **Reward** в Live и dock; журнал взаимодействий.
- Настройка скрытия строк команд только в overlay чата.

### Фаза 6c — Contribution foundation (в работе)

- Переименовать session/day/all contribution в **XP**; API, админка, dock и `/overlay/leaderboard` показывают `xp` / `session_xp` / `day_xp`.
- Заменить неограниченные баллы за каждое сообщение на тихую **activity**-награду с интервалом и лимитом за стрим (без баннера).
- Отделить Credits и уровни — позже; расширить каталог awards (`Intel`, `Spotter`, `MVP`, …) — отдельный срез.

### Фаза 6d — достижения и уровни

- Вычислять прогресс из долговечного журнала взаимодействий без полного архива чата.
- Стандартные редактируемые шаблоны и пользовательские достижения.
- Однократные и секретные unlock, уровни по XP, событие для overlay.

### Фаза 6e — Reward Library и redemptions

- Библиотека one-liners, sounds, memes, animations, popups и splash screens.
- Цена в Credits, cooldown, длительность, роли и локальные медиа.
- Надёжная очередь показа; явные состояния redemption и возврат Credits при ошибке.
- Только overlay-actions; без управления игрой и произвольного выполнения кода.

### Фаза 6f — Interactive Rules Engine

- Общая модель `Trigger → Conditions → Actions`.
- Команды как один из trigger и совместимый простой редактор поверх правил.
- Условия по балансу, роли, cooldown и лимиту сессии.
- Действия для overlay, звука, начисления и списания Credits.

### Фаза 6g — Community Awards

- Исследовать доступные реакции и эквивалентные сигналы для каждого connector.
- Настраиваемые пороги уникальных участников и временные окна.
- Защита от самонаграждения, повторов и накрутки.
- Автоматический award grant только для надёжно нормализованных сигналов.

### Фаза 6h — режиссура leaderboard

- Автопоказ по правилу или таймеру, timeout и fade внутри Browser Source.
- Автоматическое обновление уже реализовано; прямое переключение сцен OBS не входит в первый срез.

### После Interactive System v1

- Сравнить модель со StreamElements, Streamlabs, Twitch Channel Points и Mix It Up и искать конкретные пробелы.
- Отдельно исследовать предсказания, баунти, состояния персонажа, события игры, ключевые слова в обычном тексте, TTS, LLM и plugin-boundary.

## Сознательно не делаем на этом горизонте

- Облачная «глобальная» база, аккаунты CommRelay, синхронизация между ПК.
- Перенос `config.json` в SQLite.
- Полный лог всех сообщений в БД.
- Неудаляемый встроенный пак команд / жёсткая привязка ядра к MW5.
- Склейка «угадай сам по нику» без подтверждения оператора.
- Расходование Session Score или XP: покупки используют отдельные Credits.
- Произвольный JavaScript, запуск программ и прямое управление игрой из rules engine v1.
- Обещание одинаковых community reactions на платформах, connector которых не отдаёт надёжный сигнал.
