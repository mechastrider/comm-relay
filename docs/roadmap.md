# Roadmap — CommRelay

Канон **реализованного** поведения: [`openspec/specs/`](../openspec/specs/). Продуктовый бриф (что уже есть и зачем): [`concept.md`](concept.md). Этот файл — **следующий горизонт**: куда растём и в каком порядке.

---

## Статус

**Стримовый MVP достигнут** (этапы 1–5 в концепте): Twitch, YouTube Live, VK Live, единый чат, админка, OBS overlay и dock, эмоты, пресеты, `config.json`.

Дальше CommRelay остаётся **локальным** приложением (один процесс, localhost, без облачного relay) и наращивает роль **движка событий стрима**:

```text
Chat (любая платформа) → Event → Action
                              ├─ /overlay              чат (уже есть)
                              ├─ /overlay/leaderboard  лидерборд
                              ├─ /overlay/alert        попап команды (позже)
                              └─ позже: звук, TTS, игра, …
```

Контент стрима (портреты, подписи, тематика MW5) — **настройки оператора**, не ядро продукта.

---

## Хранение

| Слой | Где | Что |
|------|-----|-----|
| Настройки оператора | `config.json` | платформы, overlay, секреты OAuth/SOCKS, пресеты, граница суток |
| Зрители и факты | SQLite рядом с конфигом | идентичности, склейки, счётчики, сессии; позже — команды |

Конфиг **не** переносится в SQLite: вложенные пресеты, секреты и ручное редактирование уже работают. Оба файла лежат в одном каталоге; бэкап = копия папки.

SQLite — встроенный, **pure Go** (без CGO), чтобы сохранить один исполняемый файл на Windows/macOS/Linux.

Полный архив чата в БД **не** входит в ближайшие фазы: только агрегаты по зрителю. Кольцо последних сообщений в памяти остаётся для админки, dock и overlay.

---

## Зрители и склейка

Сообщение с платформы всегда привязано к **идентичности** `(platform, user_id)`. Канонический **зритель** может иметь несколько идентичностей (Twitch + YouTube, два аккаунта на одной платформе и т.д.).

```text
identity (twitch, 123)  ──┐
identity (youtube, UC…) ──┼─ viewer #42  →  message_count, score
identity (vk, 99)       ──┘                 (после склейки)
```

Пока склейки нет, каждый новый `(platform, user_id)` создаёт своего зрителя. Отображаемое имя и аватар — last-seen с идентичности; оператор может задать имя канонического зрителя в админке.

**Склейка** доступна в любой момент, но основной сценарий — **после стрима**: оператор видит двух людей, понимает что это один, и сливает в одного зрителя. Счётчики складываются, идентичности начинают указывать на каноническую запись, лидерборд показывает одну строку.

В админке нужно **отдельное управление зрителями**: поиск по имени / логину / id платформы, карточка (идентичности, счётчики за стрим / сутки / всё время), действие «склеить с…». Разъединение сразу не обещаем; факт склейки стоит журналировать, чтобы потом можно было подумать про undo.

Лидерборд и статистика всегда считаются по **каноническому зрителю**, не по сырой идентичности.

---

## Счётчики

Два независимых числа:

- `message_count` — сколько строк чата пришло (факт).
- `score` — баллы, которыми оператор поощряет поведение.

В ближайшей перспективе баллы начисляются **за сообщения** (отдельное поле, не «просто число сообщений»). Формула — настройка (например N баллов за сообщение), чтобы позже команды и другие события могли добавлять баллы, не ломая историю сообщений.

---

## Периоды лидерборда

Три независимых среза. Один эфир через полночь **не** должен ломать «этот стрим».

| Период | Как начинается / сбрасывается |
|--------|-------------------------------|
| `session` | Кнопка **«Новый стрим»** в админке закрывает текущую сессию и открывает новую. Пока сессии нет — она открывается при необходимости (чтобы первая установка работала без кнопки). |
| `day` | Календарные сутки оператора с **настраиваемым часом сброса**, по умолчанию **06:00** локального времени, **не полночь**. Эфир 22:00–02:00 при сбросе в 06:00 остаётся одним «днём». |
| `all` | Никогда не сбрасывается. |

Сессия и сутки независимы: ночной стрим может быть одной сессией и одним `day` (при сбросе в 06:00) или пересечь границу суток, если эфир задевает час сброса.

OBS Browser Source: `/overlay/leaderboard` с query вроде `period=session|day|all`. Чат `/overlay` не смешивается с лидербордом — это **вторая панель** в сцене.

## Команды чата (не в первом change)

Встроенного набора команд в продукте **нет**. Оператор собирает свои команды в админке (триггер, включено, кулдаун, картинка/аватар, надпись, дельта score). Для документации допустимы нейтральные примеры вроде `!gg` / `!hi`, которые оператор создаёт сам и может удалить. Тематика стрима (Джейк, ComStar, …) — содержимое этих настроек, не код CommRelay.

Обработка на **сервере** (не в overlay JS): сообщение → команда → событие → `/ws` → панель `/overlay/alert` (аватар + надпись на несколько секунд). Клиенты чата игнорируют неизвестные `type` на `/ws`.

Первый OpenSpec-change **не** реализует команды, схему команд и панель алертов. Сначала база зрителей, склейка, статистика и лидерборд.

## Фазы

### Фаза 6a — зрители, статистика, лидерборд (следующий change)

- SQLite рядом с `config.json`, миграции схемы.
- Идентичности, канонические зрители, склейка, админка зрителей.
- Учёт `message_count` и `score` (начисление баллов за сообщения).
- Сессии («Новый стрим»), сутки с часом сброса, всё время.
- OBS-панель `/overlay/leaderboard`.

### Фаза 6b — команды

- Админка команд (CRUD), пустой каталог по умолчанию.
- Серверный парсер, кулдаун, дельта score.
- OBS-панель `/overlay/alert`.

### Позже (не планировать, пока 6a/6b не на стриме)

Ранги, валюта, предсказания, баунти, состояния персонажа, события игры, ключевые слова в обычном тексте, LLM, plugin-boundary коннекторов.

---

## Сознательно не делаем на этом горизонте

- Облачная «глобальная» база, аккаунты CommRelay, синхронизация между ПК.
- Перенос `config.json` в SQLite.
- Полный лог всех сообщений в БД.
- Неудаляемый встроенный пак команд / жёсткая привязка ядра к MW5.
- Склейка «угадай сам по нику» без подтверждения оператора.
