# Стратегия браузерных регрессий

Playwright проверяет связку собранной админки, Go API, SQLite и браузера.
Каждый тест получает отдельные сервер, порт, config и базу с тремя известными
зрителями; тест каталога на 1003 зрителя расширяет эту же фикстуру. Реальные
платформы отключены. Это не проверка Twitch/YouTube/VK или установленного Wails/OBS.

## Распределение ответственности

| Набор в `web/e2e/` | Уникальный риск и пересечения | Браузеры / стоимость |
| --- | --- | --- |
| `admin` | Прямые ссылки, history, сохранение sidebar; геометрия основных страниц на широком, коротком и узком экранах. Обзорные снимки дублировали эти проверки и локальные снимки `parity`. | Chromium; history/storage и геометрия — также Firefox/WebKit. Низкая стоимость без фиксации каждого текста в PNG. |
| `workflows` | Сохранение и повторная загрузка настроек; dirty guards; CRUD команд/наград; приветствия, progression, merge, публикация Studio, выдача награды победителю. Unit-тесты моделей не заменяют реальную запись через UI. | Chromium; responsive viewer editor также в других движках. Средняя стоимость, сохраняем все сценарии. |
| `live-events` | WS → DOM, дедупликация, безопасный текст, удаление, награда через Go; восстановление загрузки viewer; локаль и клавиатура. Чистые редьюсеры отдельно в unit. | WS и клавиатура — три движка; API retry — Chromium. |
| `media-and-settings` | Upload → публикация → очистка реального файла; validation/OAuth polling; отказ localStorage; архив после restart. OAuth здесь подменён, не проверяет провайдера. | Файлы, storage, focus — три движка; архив — Chromium. |
| `resilience` | HTTP 503 с сохранением черновика и чужой секции; настоящий WS reconnect; изолированный канал overlay; PNG download и native bridge cancellation; загрузка всех OBS поверхностей. | Browser API/WS/download/прозрачность — три движка; HTTP-merge — Chromium. |
| `operator-polish` | Настоящий AudioContext и WAV playback, громкость, переходы и сохранённое выключение; геометрия leaderboard во всех темах и прямоугольниках. | Три движка: замена unit-моками потеряла бы покрытие. Самый широкий геометрический цикл сохранён. |
| `studio-tooltip` | Hover/keyboard tooltip, clipping предками и scroll inspector. | Chromium на четырёх размерах; Firefox/WebKit на широком и узком. Без снимков каждого hover. |
| `visual-consistency` | Размеры действий, секции форм, focus ошибок, отсутствие разрыва слов в tooltip, RU/EN. JSDOM не измеряет layout. | Полная сетка Chromium; RU wide/narrow также другие движки. Остальные варианты проверяют ту же реализацию CSS. |
| `ux-audit` | Setup vs disconnected, network abort, recovery notice, компактная Studio, доступность, справочники правил, pagination/search/dirty guard. HTTP 503 и network abort — разные ветки, не удаляем как «дубль». | Chromium; clipping и keyboard semantics — три движка. Каталог 1003 строк сохраняет замер navigation→rows. |
| `parity` | Заполненная таблица, inspector/sheet, OBS setup dialog на трёх размерах. | Только Chromium/Linux, девять локальных эталонов значимых состояний. |
| `overlay-visual` | Chat, leaderboard, alert непосредственно в Browser Source: пять тем, текст и композиция. Раньше chat косвенно попадал в полный снимок Studio, остальных эталонов не было. | Только Chromium/Linux. Эталон поверхности, а не всей админки. |

Go-тесты отвечают за валидацию/config, command matching, начисления, API и
хранилище. `npm test` включает Node-тесты статических поверхностей и Vitest:
API errors, ресурсы/пагинацию, live reducer, command-audio scheduler и mocked
media, RichMessage, desktop save bridge, модели форм. Они проверяют больше
комбинаций данных, чем стоит повторять через браузер; проверок всей React-формы
с реальным сервером там нет. Поэтому поведенческие e2e не удаляются только
из-за наличия unit-теста с похожим названием.

## Правила покрытия

- `@core`: сохранение настроек, сообщения/награда, CRUD команд/наград, выдача
  победителю, звук, публикация Studio, изолированная доставка overlay и OBS
  surfaces. Быстрая обязательная проверка ключевых связок; не замена всего CI.
- `@browser`: риск связан с движком — WebSocket, audio/autoplay, storage,
  upload/download, history, focus, responsive layout, clipping, прозрачность.
  Эти проверки выполняются во всех трёх браузерах.
- `@visual`: композиция, которую неудобно надёжно описать несколькими
  утверждениями. Сначала предпочитать эталон самой OBS-поверхности, затем
  важного dialog/panel. Не добавлять полный снимок страницы ради текста вкладки.

Новый e2e нужен для новой пользовательской связки или воспроизводимой браузерной
регрессии, которую нижний слой не обнаружит. В тесте указывать наблюдаемый итог:
сохранение после reload, файл в хранилище, строка награды, доставленное сообщение,
реальное `playing`. Варианты валидации, расчёты и очередь удобнее проверять unit.
Новый `@browser` должен иметь конкретную причину; новую комбинацию локали/размера
добавлять при ином breakpoint или механизме, не автоматически умножать всё на три.

Обзорные 15 PNG админки заменены проверками ширины, достижимости основных
действий/последнего поля, live tabs и готовности Studio preview. Это намеренно
отказывается от фиксации каждого отступа, декоративного элемента и текста на
About/Settings/Live. Локальные эталоны `parity` и измерения `visual-consistency`
сохраняют защиту значимых состояний и общих компонентов.

## Детерминированность и диагностика

Браузеры и Go-процессы используют UTC; локаль браузера — en-GB. Для визуальных
тестов Date фиксирован, но таймеры, animation и media не подменяются глобально.
Seed даты/ID постоянны. Динамическая диагностика подменяется только в тестах,
где она входит в снимок; случайный localhost port маскируется в OBS URL inputs.
Нельзя фиксировать часы backend через дату браузера: сроки/сессии проверять
отдельно с явными данными, не сравнивать с замороженным frontend временем.

Ожидать DOM, ответ API, handshake/frame, состояние AudioContext, завершение
анимации или вычисленную геометрию; не добавлять sleep для «стабильности».
Проверку отсутствия звука синхронизировать доставленным WS-сообщением после
alert и учитывать попытки `play()`, а не только успешное событие `playing`.
Отложенные ветки scheduler проверяются unit-тестами с fake timers.

Retries остаются 0. Не ослаблять pixel threshold, не увеличивать timeout и не
ставить skip вместо выяснения причины. Ошибка Firefox audio может означать
autoplay, отсутствие audio backend, отказ декодирования или дефект приложения;
это не доказательство flaky-теста. CI поднимает PulseAudio null sink. При
локальном запуске нужен рабочий аудиовыход (допустим виртуальный).
Например, на Linux с установленными `pulseaudio` и `pulseaudio-utils`:

```bash
pulseaudio --start --exit-idle-time=-1
pactl load-module module-null-sink sink_name=comm_relay_e2e
PULSE_SINK=comm_relay_e2e npm run test:e2e
```

`load-module` возвращает ID: после проверки его можно передать
`pactl unload-module <ID>`. Это не требует менять системный default sink.

## Команды

Штатная адресная матрица: **60 Chromium + 26 Firefox + 26 WebKit = 112**
запусков; в Chromium остаются все сценарии, включая визуальные. Восемь `@core`
входят в обычный CI, отдельной необязательной заменой не становятся.
Для диагностики регрессии движка, обновления Playwright и крупных изменений
React/router/общих форм запускать полный повтор поведенческих тестов во всех
браузерах (168 запусков с новыми проверками):

```bash
COMM_RELAY_E2E_MATRIX=full npm run test:e2e
```

Адресный набор не доказывает каждую комбинацию формы и движка: этот остаточный
риск принимается для прикладных сценариев, чьи browser-механизмы отдельно
проверяются через `@browser`. Уникальная ошибка конкретного движка — причина
пометить соответствующий сценарий, а не выключить его.

Проверка `Browser regression` в `.github/workflows/ci.yml` остаётся на каждом PR
и push в main, со всеми тремя установленными движками, двумя workers, нулевыми
retries и сохранением отчёта. Штатный `npm run test:e2e` использует адресный
выбор повторов Firefox/WebKit из `playwright.config.ts`; расписание,
обязательность job, audio backend, пороги сравнения и таймауты не меняются.

```bash
npm ci
npx playwright install --with-deps chromium firefox webkit
npm run typecheck
npm run lint
npm test
npm run test:e2e                         # build admin + Go, затем матрица
npm run test:e2e -- --project=chromium --grep @core
npm run test:e2e:visual                  # визуальные эталоны Chromium
```

После единственной сборки для итераций можно запускать
`npx playwright test web/e2e/workflows.spec.ts --project=chromium`.
После изменения продукта сначала повторить `npm run build && node scripts/e2e-build.mjs`.
`COMM_RELAY_E2E_DISK=1 npm run test:e2e` проверяет disk mode; штатный CI проверяет
embedded assets. Отчёт — `playwright-report/index.html`, trace и server log
прикрепляются при ошибке. Для замеров использовать один host, два workers,
одинаковую сборку и `--reporter=json`; отдельно учитывать build/install.
Не запускать несколько Playwright-процессов с общим `test-results`: они очищают
каталог друг друга. Для независимых запусков указывать разные `--output` и пути
отчётов; для сравнения длительности запускать последовательно.

Эталоны создаются на Linux с версией Playwright из lockfile. Для намеренного
изменения запускать узкий файл/тест с `--update-snapshots`, просматривать каждый
новый PNG и expected/actual/diff, затем повторять без обновления. Нельзя
обновлять все эталоны автоматически после падения CI. Визуальные проверки
не гарантируют вид реального OBS или Windows WebView: packaged smoke нужен
для изменений IPC, нативного сохранения, webview и установки.
WAV-тест подтверждает AudioContext readiness, настоящее событие `playing` и
громкость элемента, но не слышимость в физическом устройстве, маршрутизацию OBS
или поддержку всех пользовательских кодеков. Live-события инжектируются в WS;
matching команд и начисления в полном ingest pipeline защищены Go-тестами,
а внешние платформы требуют отдельной интеграционной проверки.

## Исходные свидетельства

Исследование начато с чистого `main` на `028fff9`; PR #93 уже слит вместе с
ожиданием AudioContext readiness, PulseAudio в CI и проверкой громкости с учётом
квантования backend. Эти исправления сохраняются.
[Исходный CI](https://github.com/mechastrider/comm-relay/actions/runs/37137844684/job/111245914310?pr=93):
159 запусков, 155 passed, три visual failures и Firefox audio, 5,3 минуты тестов.
[Последний CI PR #93](https://github.com/mechastrider/comm-relay/actions/runs/37140363663):
159 passed, также 5,3 минуты; audio: Chromium 6,8 s, Firefox 4,8 s, WebKit 5,3 s.
Это подтверждает прохождение после исправлений, но не выделяет единственную
причину старого audio failure: между запусками было несколько изменений.

## Проверка изменений 2026-10-03

Последовательные локальные прогоны на одной Ubuntu 22.04 VM, два workers,
Playwright 1.63.0 из lockfile, один embedded Go binary, PulseAudio null sink.
Исходные тесты/config/PNG прочитаны из `028fff9` в отдельную директорию;
рабочие изменения при сравнении не откатывались.

| Набор | Chromium / Firefox / WebKit | Итог | Wall time без build/install |
| --- | --- | --- | --- |
| Исходный | 57 / 51 / 51 | 159 passed | 495,6 s |
| Адресный | 60 / 26 / 26 | 112 passed | 319,4 s |

В этом замере сокращение wall time — 35,6%. Это одна пара запусков на общей VM,
не статистика стабильности и не обещание такого же ускорения GitHub CI.
Сумма длительностей Chromium-тестов практически не изменилась: 218,5 → 216,7 s;
экономия возникает в повторах Firefox/WebKit, а не в отказе от уникального
покрытия. Самый дорогой новый тест — leaderboard geometry в WebKit, 28,2 s;
он сохранён полностью.

В обоих сравнительных прогонах — ноль skips/retries/failures. Все 15 новых OBS PNG просмотрены
и затем проверены без обновления; девять `parity` PNG не менялись. Удалены
15 обзорных PNG админки и 48 диагностических hover-снимков за полный старый
прогон (это были артефакты, не эталоны). Вместо hover sleep ожидается завершение
анимации; вместо audio sleep — доставка WS и проверка попыток воспроизведения.

Дополнительно прошли `npm ci`, build админки и Go-сервера, TypeScript, ESLint,
39 Node-тестов статических поверхностей, 30 Vitest-тестов,
`go test ./internal/api ./internal/config`, `golangci-lint run ./...` (0 issues)
и `git diff --check`. Штатный выбор после включения матрицы отдельно сверён
с 112 успешно выполненными тестами. Новый GitHub CI и packaged Wails/OBS smoke
из этой сессии не запускались; исходный полный набор не заменяет проверку
изменений после их публикации.
