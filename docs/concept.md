# Проект: Chat Relay (рабочее название)

## Цель проекта

Разработать самостоятельное приложение на Go для агрегации чатов стриминговых платформ и вывода сообщений в OBS через Browser Source.

Приложение не является частью существующего проекта mech-comm и развивается как отдельный продукт.

Основная задача — обеспечить стабильное отображение сообщений из нескольких платформ одновременно без зависимости от сторонних сервисов и облачных решений.

---

# Основные требования

## Поддерживаемые платформы

MVP:

- Twitch
- YouTube Live

После MVP:

- VK Live / VK Video
- Kick
- Trovo (опционально)

---

# Архитектура

Приложение представляет собой локальный сервер.

Состав:

1. Коннекторы платформ
2. Внутренний агрегатор событий
3. HTTP-сервер
4. WebSocket-сервер
5. Веб-интерфейс управления
6. Overlay для OBS

Схема:

[Twitch]  
[YouTube] --> [Chat Relay Core] --> [WebSocket] --> [OBS Overlay]  
[VK Live]

# Единая модель сообщения

Все платформы должны преобразовываться к единому формату.

Пример структуры:

```go
type ChatMessage struct {
    ID          string
    Platform    string
    UserID      string
    Username    string
    DisplayName string

    Message     string

    AvatarURL   string

    Badges      []string

    Timestamp   time.Time
}

```

Overlay не должен знать ничего о Twitch, YouTube или других платформах.

# Коннектор YouTube

Использовать:

- YouTube Live Chat API

Требования:

- OAuth авторизация
- получение сообщений
- автоматический polling
- обработка ошибок квот

---

# Внутренний Event Bus

Все коннекторы публикуют события в общий канал.

Пример:

```go
type Event struct {
    Type string
    Data any
}

```

Типы событий:

- ChatMessageReceived
- UserJoined
- UserLeft
- StreamStarted
- StreamStopped

На MVP достаточно ChatMessageReceived.

# WebSocket API

Назначение:

Передача сообщений в overlay в реальном времени.

Endpoint:

/ws

Формат:

```json
{
  "type": "message",
  "platform": "twitch",
  "user": "Commander",
  "message": "Hello"
}

```

# OBS Overlay

URL:

# Панель управления

# Нефункциональные требования

- Один исполняемый файл.
- Работа на Windows без установки дополнительных компонентов.
- Минимальное потребление памяти.
- Возможность запуска на втором ПК для стриминга.
- Отсутствие внешних облачных зависимостей.
- Простое локальное развертывание.
